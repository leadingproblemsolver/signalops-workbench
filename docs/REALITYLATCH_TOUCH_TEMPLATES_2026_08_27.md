# RealityLatch value-first touch templates — 2026-08-27

These are operator-review templates. They are not authorized for autonomous sending.

## Rapport-first first touch

Use only when there is a real, verifiable human signal.

Structure:

1. Name the specific public contribution or operational theme.
2. Add one useful observation connected to that theme.
3. No case request, meeting request, demo request, or referral request.

Example shape:

> Your work around [verified operational theme] made me think about a failure mode I keep seeing in exception systems: the physical action can be complete while evidence still leaves ownership unresolved. I mapped that distinction because it seems especially relevant where ERP/WMS/CRM states have to agree. No ask — sharing because the boundary may be useful.

## Useful-artifact-first first touch

Structure:

1. Name the public operational change.
2. State that the artifact uses public information only.
3. Deliver the artifact.
4. Mark assumptions/unknowns visibly.
5. Ask only for the easiest correction.

Example shape:

> I mapped three places where the new [publicly announced operation/capability] could create exception handoffs. This is based only on public information, so the parts I cannot know from outside are explicitly marked UNKNOWN. Sharing the map first because it may be useful. If you look at it, the most useful response is literally “#2 doesn’t happen here” or “you missed X.”

## Micro-pilot first touch

Structure:

1. Show the finished five-line example/output format.
2. Fix the input size in advance.
3. Fix the return in advance.
4. Make the review binary/ternary.

Example shape:

> Here is the exact reconstruction format I’m testing: EVENT → EVIDENCE → CURRENT OWNER → ACTION ALREADY HAPPENED? → CONTRADICTION → SETTLED/NOT SETTLED. If it maps to a problem you actually see, redact names from one exception and send whatever five event lines already exist. I’ll return the reconstruction. Your only review is useful / partial / wrong.

## Follow-up rule

A follow-up is allowed only when it contains new value: a revised artifact, a correction incorporated from public evidence, or a genuinely new relevant observation. Never repeat the same ask in different words.

## Adoption boundary

- reply != adoption
- meeting != adoption
- click/view != adoption
- `pilot_used` is first adoption evidence
- `second_use` is stronger retention evidence
- purchase is economic evidence
