# Hackathon/company routing

Owner remains this repo. Do not create a new hackathon-engine repo.

For every opportunity:
live requirement -> choose strongest existing artifact -> smallest adapter -> test -> hostile verify -> CI/demo -> external review/submission -> receipt -> reuse for company/job/customer.

Routing priority:
1. existing artifact already closest to requirement
2. external reviewer/judge/company visibility
3. smallest implementation delta
4. measurable failure/correction boundary

Kill anything that requires speculative rebuilding before external evidence.
